# Робо — семейный AI-ассистент

Telegram-бот для общей семейной памяти. Заметки составляются в диалоге с ИИ,
а на вопросы бот отвечает, находя релевантные записи (по дате, человеку, теме,
автору) — а не вываливая всё подряд.

## ✨ Возможности

- **Диалоговые заметки** — пишешь мысль, ИИ предлагает формулировку, правишь
  словами, сохраняешь финальную версию.
- **Умный поиск контекста** — вопрос → профиль поиска (теги/люди/период/автор)
  → срез заметок → ответ. Работают «что завтра?», «заметки от Тани», «что по покупкам».
- **Машинные даты событий** — «завтра в 10» сохраняется как `event_date`, поэтому
  «что завтра?» ищет по реальной дате, а не по тексту.
- **Желания** — бот отличает желания (`/wishes`) и фиксирует их исполнение (`/fulfilled`).
- **Теги** — typed (`topic:/person:/type:`), помогают находить и фильтровать.
- **Редактирование** — `/edit_<id>` правит заметку в том же диалоге.
- **Память сессии** — последовательные уточнения («а во сколько?») работают ~15 мин.
- **Таймзоны** — у каждого своя (по геолокации), «сегодня/вчера» считаются корректно.
- **Сменный провайдер LLM** — OpenAI (по умолчанию) или Anthropic, одной переменной.

## 🔐 Модель приватности

Уровней видимости **нет** — всё, что сохранено, видит вся семья. Приватность
обеспечивается иначе: **сырого ввода в БД не хранится вообще**. Ты составляешь
заметку в диалоге и сохраняешь только ту формулировку, которую сам утвердил.
Что не должно попасть в общую память — просто не сохраняется. Честно: админ
(владелец сервера) видит ровно то, что лежит в БД, то есть согласованные заметки.

## 🚀 Локальный запуск

```bash
git clone https://github.com/deva1056/oikos.git
cd oikos
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env        # заполни переменные (см. ниже)
python -m bot.main          # нужен доступный PostgreSQL (DATABASE_URL)
```

> БД — только **PostgreSQL** (SQLite не используется). Локально подними Postgres
> и укажи `DATABASE_URL`, либо тестируй на Railway.

## 🌐 Деплой на Railway

1. New Project → Deploy from GitHub → репозиторий `oikos`.
2. `+ New` → Database → PostgreSQL (создаст `DATABASE_URL` автоматически).
3. Variables — задай переменные окружения (таблица ниже).
4. Push в `main` → Railway деплоит автоматически. Логи: сервис → Logs (`✅ Робо запущен`).

## ⚙️ Переменные окружения

| Переменная | Обязательна | Назначение |
|---|---|---|
| `TELEGRAM_TOKEN` | да | токен бота от @BotFather |
| `ALLOWED_IDS` | да | Telegram ID членов семьи через запятую (@userinfobot) |
| `DATABASE_URL` | да | PostgreSQL (на Railway создаётся сам) |
| `LLM_PROVIDER` | нет | `openai` (дефолт) или `anthropic` |
| `OPENAI_API_KEY` | при openai | ключ OpenAI |
| `OPENAI_MODEL` | нет | модель OpenAI (дефолт в коде) |
| `ANTHROPIC_API_KEY` | при anthropic | ключ Anthropic |
| `ANTHROPIC_MODEL` | нет | модель Anthropic |
| `TIMEZONE` | нет | дефолтная таймзона до определения (дефолт `Europe/Prague`) |
| `SESSION_TTL_MIN` | нет | таймаут сессии диалога, мин (дефолт 15) |

## 📋 Команды

| Команда | Что делает |
|---|---|
| `/start` | регистрация + запрос геолокации для таймзоны |
| `/note <текст>` | начать заметку (override классификации) |
| `/ask <вопрос>` | спросить память (override) |
| `/notes` | твои заметки (с `/edit_<id>`) |
| `/edit_<id>` | редактировать заметку в диалоге |
| `/tags` | все теги семьи с частотой |
| `/tag <тег>` | заметки с тегом |
| `/addtag <id> <тег...>` | добавить тег(и) |
| `/rmtag <id> <тег>` | убрать тег |
| `/retag <id>` | переосмыслить теги через LLM |
| `/wishes [имя]` | открытые желания (с кнопкой «Сбылось») |
| `/fulfilled [имя]` | сбывшиеся желания |
| `/done <id>` / `/cancelwish <id>` | отметить/отменить желание |
| `/timezone [IANA]` | задать таймзону (или геолокацией) |
| `/members` · `/clear` · `/help` | участники · удалить свои заметки · справка |

Свободный текст: утверждение → диалог-черновик; вопрос → ответ из памяти.

## 🛠️ Стек

- Python 3.9+, `python-telegram-bot` 22.5+ (async)
- LLM: OpenAI / Anthropic (переключается `LLM_PROVIDER`)
- PostgreSQL (`psycopg2`, пул соединений)
- `timezonefinder` (таймзона по координатам), `tzdata`
- Хостинг: Railway

## 📁 Структура

```
core/                 # бизнес-логика (без Telegram)
  db.py               # пул соединений + схема (init_db)
  memory.py           # CRUD заметок, теги, желания
  ai.py               # провайдер LLM, экстракторы, ответы
  retrieval.py        # вопрос → профиль → срез контекста
  timeutils.py        # таймзоны, границы периодов
  auth.py             # whitelist
bot/
  main.py             # сборка хендлеров и запуск
  handlers/           # start, draft (диалог/черновик), commands,
                      # location, session (TTL-память), _send
scripts/              # миграции и обслуживание БД (см. ниже)
```

## 🧰 Скрипты обслуживания (запуск с `DATABASE_URL`)

- `migrate_to_single_field.py` — миграция со старой 3-уровневой схемы (разово).
- `normalize_existing_tags.py` — нормализация тегов (`--dry`).
- `retag_notes.py [--all] [--dry]` — переосмыслить теги через LLM.
- `seed_test_data.py` / `delete_by_tag.py <tag>` — тестовый набор и его удаление.
- `delete_notes.py <id...>` — удалить заметки по id.
